# Development

*Translated from French - the French version is authoritative.*

Documentation to understand the architecture and extend the project (core,
plugins, themes).

## 1. Architecture

```
public/                front controller (index.php) + assets
app/src/MXWebMail/     application code:
  Application/App.php  service container + dispatch + routes
  API.php, Utils.php   compatibility facades for vendored code (MailSo/Lib)
  Compat/              MailSo compatibility bridges (ActionsBridge,
                       ConfigBridge, PluginsBridge)
  Config/              configuration loading/writing
  Controller/          PageController, ApiController, AdminController,
                       SetupController (/setup wizard, served as long as
                       storage/INSTALLED is absent - 404 afterwards) ;
    Api/               API controllers by domain (Messages, Folders,
                       Contacts, Compose, Accounts, Settings, Filters,
                       Pgp, Poll)
    Admin/             admin controllers by tab (System, Domains, Users,
                       Plugins, Themes)
  Http/                Router, Request, Response, JsonResponse
  Locale/              Translator + dictionaries
  Plugin/              HookRegistry, PluginManager, PluginBase
  Repository/          data access (Database, User*, Domain, Plugin, Theme…)
  Security/            Csrf, CredentialCrypt, Headers, IpMatch, TotpRequiredException, Wildcard
  Service/             AuthService, MailService, DomainDetector, OAuthService,
                       GitHubClient (shared Releases HTTP), UpdateService (core),
                       PluginPackageService (plugin catalog/install/remove),
                       contact imports (CsvContacts, VCardContacts,
                       RainLoopContacts)
  Sieve/               ScriptBuilder - filter rule generation
  Theme/               ThemeManager
app/src/MailSo/        vendored mail library (unmodified)
app/src/Sabre/         sabre/vobject+xml+uri (vCard CardDAV)
app/src/Lib/           MXWebMailLib utilities (classmap)
app/src/bootstrap.php  home-made autoloader
```

- **Frontend**: Knockout + Bootstrap 5.3, ES modules in `public/assets/js/`
  (app.js, viewmodels/, models/, bindings/, ui/).
- **No Composer**: home-made autoloader (see §2).

## 2. Autoloader (`app/src/bootstrap.php`)

- **PSR-4**: `MXWebMail\` > `app/src/MXWebMail`, `Sabre\` > `app/src/Sabre`.
- **Case-insensitive classmap**: `MailSo\` > `app/src/MailSo`, `MXWebMailLib\` >
  `app/src/Lib` (legacy code, lowercase filenames, multi-class). Generated by
  `token_get_all` scan, cached in `app/storage/cache/classmap.php`, rebuilt
  automatically on miss (once per request).
- Loads the `functions.php` of sabre/uri and sabre/xml ("files" autoload).

## 3. Core hooks

Plugins register on: `app.routes`, `app.head`, `app.data`,
`auth.login.mapping`, `auth.login.mapped`, `auth.provider`, `auth.post-login`,
`contacts.provider`,
`identities.provider`, `password.change`, `settings.allowed`,
`imap.before-connect`,
`imap.message-headers`, `sieve.before-connect`, `smtp.before-connect`,
`message.meta`,
`message.view`, `message.before-send`, `message.spam`, `attachment.upload`,
`admin.mounts`, `admin.post-login`,
`admin.totp-required`.

On the admin panel: `admin.mounts` (collect) feeds the bootstrap's
`adminMounts` - `{js, plugin, section, tab?, label?}` descriptor mounted via the
`pluginMount` binding (opt `admin: true` > `ctx.admin`, the module's calls are
prefixed `/admin/plugin/…` toward `Plugin::apiAdmin<Action>`). Without `tab`:
inline block in the `section` zone (e.g. `security-account`); with `tab` +
`label`: dedicated sub-tab of the `section` page (e.g. `security` >
`#/security/<tab>`), rendered only if the plugin is enabled. The special
`'page'` section (+ optional `icon`, Font Awesome class) creates a
**top-level page** in the side menu (`#/<tab>`). `admin.post-login` is emitted
at local admin account login; throwing `TotpRequiredException` there locks
access (e.g. admin TOTP).

See [plugins.md](plugins.md) to build a plugin.

## 3bis. Plugin distribution (GitHubClient + PluginPackageService)

- `GitHubClient` pools GitHub access for `UpdateService` (core package
  `mxwebmail-*.zip` via `coreAsset`) and `PluginPackageService` (reading the
  repo at ref `update.plugins_ref`: `resolveCommit()` >
  `GET /commits/<ref>` gives sha + tree sha, `tree()` >
  `GET /git/trees/<sha>?recursive=1` maps the `app/plugins/**` blobs,
  `rawUrl()` > `raw.githubusercontent.com` pinned on the commit sha).
  Repository locked by the `REPO` constant, shared release cache
  `storage/cache/update-check.json`. Every truncated asset carries
  `download_url`, resolved by `pickUrl()`: API endpoint
  `releases/assets/<id>` (`Accept: application/octet-stream`) if a PAT is
  configured in `config.php` - required on a private repo where
  `browser_download_url` returns 404 - otherwise `browser_download_url`.
  Plugin caches: `plugins-ref.json` (TTL `update_ttl`), `plugins-tree-<sha>.json`
  and `plugin-manifest-<name>-<sha>.json` (immutable).
- `PluginPackageService`: `catalog()`, `install()` (stages each file via raw >
  size + `blobId()` git sha1 check > `plugin.json` validation +
  `min_app`/`max_app` > swap with a single backup per plugin > classmap/opcache
  invalidation), `remove()` (rmrf + purge of the `plugins` row via
  `PluginRepository::delete()`). Shared lock `storage/update/update.lock` with
  `UpdateService`. Staging in `storage/update/plugins/`. Alternative source
  `update.plugins_local` (disk, dev/tests, no remote verification).
- The release zip packaging excludes `app/plugins/*` from the core zip - no
  plugin asset is published: bump `version` in `plugin.json` + push to the
  tracked branch = publication. The zip also excludes the repo meta files
  (`.github/`, `docs/`, `README.md`, `CHANGELOG.md`, `SECURITY.md`,
  `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`); `LICENSE` stays distributed.

## 4. Cache & compression

Everything is configurable (admin > *Performance*, `http.*` / `cache.*` sections
of `config.php`):

- **Compression**: `App::sendResponse()` calls `Response::gzip()` at the single
  send point - covers `php -S`, Apache and Nginx. Already-encoded responses or
  non-compressible types are skipped; `Vary: Accept-Encoding` is set as soon as
  the type is compressible. `zlib.output_compression` active > no-op.
- **Static assets** (`public/assets/img|js|vendor`): served by the web server
  under the versioned URL `/assets/v<APP_VERSION>/…` (`public/.htaccess`
  rewrite, nginx `location` block documented in installation.md). 1-year
  immutable TTL under Apache; the dev server serves `no-cache`.
- **PHP assets** (`/assets/theme/{n}/{f}`, `/assets/plugin/{n}/{f}`, favicon):
  `PageController::serveAsset()` sets `Cache-Control` from `http.assets_ttl` /
  `http.favicon_ttl` (+ `immutable` if `?v=` present) and, when `http.etag`,
  `ETag`/`Last-Modified` > `304` on `If-None-Match`. The `?v=` come from
  `theme.json`/`plugin.json` (`ThemeManager::version`, `PluginBase::version`) -
  a targeted component bump busts its own cache.
- **Server cache**: `ActionsBridge::Cacher()` returns a driver-less client when
  `cache.enabled=false` (Get/Set no-op). Periodic GC (`cache.gc_hours`, marker
  `storage/cache/_gc.ts`) - purges all files in the folder, including
  `classmap.php` (rebuilt on the next request). Dedicated TTLs:
  `cache.domain_detect_ttl` (detection), `cache.update_ttl` (releases).
- **HTML**: `no-cache` - the shell always references the current version's
  assets. API/private responses never get a public TTL.

## 5. Project conventions

- **Bootstrap**: a single JS component per element (`Data`) - never `tooltip:`
  (or another binding) on a `data-bs-toggle` element; put it on the child icon.
- **Versioning** semver `0.MINOR.PATCH`: `PATCH` = fix/refactor, `MINOR` =
  feature or breaking change. Targeted bump: `APP_VERSION` (core) or
  `plugin.json`/`theme.json` (modified component). No global bump on every
  commit.
