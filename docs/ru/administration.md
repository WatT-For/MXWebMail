# Администрирование

*Переведено с французского - французская версия является исходной.*

Панель администрирования доступна по `/{admin_path}` (по умолчанию `/admin`).
Это **глобальное** администрирование (мультидоменное); тонких ролей нет.

## 1. Аутентификация админа

Два режима в зависимости от конфигурации:

1. **Локальный аккаунт** (`admin_user` + `admin_password_hash` в
   `config.php`): логин/пароль, возможно TOTP (`admin_totp_secret`). TOTP
   провизионируется и применяется плагином `two-factor-auth` (под-вкладка
   "Двухфакторная аутентификация" раздела *Безопасность*, с QR-кодом) -
   плагин выключен = не требуется при входе.
2. **IMAP-fallback** (без локального аккаунта): пользователь,
   аутентифицированный через IMAP с полем `is_admin = 1`, открывает админ.
   Это право ревалидируется при каждом запросе (пониженный/заблокированный/
   удалённый аккаунт немедленно отклоняется).

Rate-limit входа применяется и к админу, как и `admin_ip_allowlist`, если
заполнен. IMAP-админ не может понизить, заблокировать или удалить себя.

## 2. Разделы панели

Панель состоит из вкладок (hash `#/<страница>[/<под-вкладка>]`).

### Общие

`app_name`, `admin_path`, `language` (список установленных языков +
`auto`), `session_lifetime`, `remember_days` (срок токенов "Оставаться в
системе"), `maintenance`, `update.channel`. Управляет также **favicon**
(загрузка ≤ 512 КБ: ico/png/svg/jpg/webp, содержимое валидируется). Режим
**обслуживания** показывает выделенную страницу (503) на `/`: подключённые
пользователи переключаются на неё при следующем API-запросе (сессия
сохраняется), и она сама перезагружается в конце; админ (`/{admin_path}` +
`/api/admin/*`) остаётся полностью доступен.

### База данных

Драйвер SQLite или MariaDB/MySQL, host/порт/имя/пользователь/пароль. Тест
(`/api/admin/test-db`) обязателен до записи: сервер валидирует подключение и
создаёт базу при необходимости. См.
[base-de-donnees.md](base-de-donnees.md).

Карточка **Резервная копия** скачивает zip-архив (`config.php`, `app.key`,
SQLite-базы, `storage/branding`) - **чувствительный** (учётные данные +
ключ шифрования), хранить в безопасном месте. База MariaDB не покрывается:
`mysqldump` на стороне сервера.

### Функциональность

Под-вкладки *Функциональность* и *По умолчанию*:

- прокси изображений + allowlist, размеры вложений;
- `contacts_enable` / `contacts_suggestions_limit`;
- `allow_additional_accounts` / `allow_additional_identities`,
  `popup_identity`, `dangerous_actions`;
- все настройки `user_defaults.*` (дефолты пользователей).

### Производительность

Под-вкладки *HTTP* и *Серверный кэш*:

- `http.*`: gzip-сжатие (включение, уровень, минимальный размер),
  `http.etag`, TTL ассетов темы/плагинов, favicon и прокси изображений;
- `cache.*`: файловый прикладной кэш (включение, TTL детекции домена и
  проверки обновления, интервал очистки).

Детали ключей в [configuration.md](configuration.md) (разделы *HTTP* и
*Прикладной кэш*).

### Безопасность

Под-вкладки *Аккаунт*, *Двухфакторная аутентификация* (если плагин
`two-factor-auth` активен), *Доступ*, *Заголовки*, *TLS*:

- локальный админ-аккаунт (`admin_user`) и **смена пароля** админа -
  заполните оба поля, затем *Сохранить*: пароль меняется только если они
  заполнены и идентичны;
- **TOTP** админа (под-вкладка плагина `two-factor-auth`): генерация
  секрета, QR-код для сканирования, обязательный код подтверждения до
  включения (секрет никогда не показывается после сохранения);
- `admin_ip_allowlist` (кнопка "добавить мой IP"), `login_max_attempts` /
  `login_lock_seconds`, `trusted_proxies`;
- `force_https`, `hsts`, `cookie_samesite`, `csp_extra`, `secfetch_allow`;
- полная секция `ssl.*` (исходящие сертификаты).

### Журналы

Под-вкладки *Просмотр* и *Параметры*:

- просмотр журналов `app.log`, `mail.log` и журнала auth (последние 200
  строк), с кнопкой "Очистить" для усечения выбранного файла;
- `debug`, `logs.*`, `auth_logging*`, `labs.smtp_show_server_errors`.

### Домены

Настройка почтовых серверов по доменам - см. [domaines.md](domaines.md).
Вкладка *Параметры* группирует разрешение (`default_domain`,
`restrict_domains`, `autodetect.*`). Для доменов "только дополнительный
аккаунт + OAuth-провайдер" (Gmail, Outlook, Yahoo) админ только авторизует
провайдера (опция `oauth` модала домена): учётные данные OAuth2-приложения
регистрирует каждый пользователь (*Настройки > OAuth2-приложения*).

### Пользователи

Список + поиск пользователей, с кнопкой обновления (иконка) для перезагрузки
списка. На пользователя (модал, вкладки *Профиль*, *Настройки*,
*Аккаунты/Идентичности*, *Сессии*):

- `display_name`, `is_admin`, `disabled`;
- эффективные настройки пользователя (редактирование + сброс - сброс
  восстанавливает `user_defaults`, но **сохраняет** внутренние ключи
  `plugin.*` и `user_folders`, напр. секрет 2FA, происхождение папок);
- дополнительные IMAP-аккаунты (удаление, кроме аккаунта по умолчанию);
- идентичности (создание/редактирование/удаление, идентичность по
  умолчанию);
- вкладка **Сессии**: токены "Оставаться в системе" перечислены и
  отзываемы; **Принудительный выход** отзывает токены и убивает активные
  сессии (session_epoch инкрементирован, отказ при следующем запросе).

Удаление пользователя каскадно и удаляет также его контактную базу
(`storage/db/users/<id>.sqlite`).

### Расширения (плагины)

Каждый плагин перечислен под своим **отображаемым именем** (поле `label`
манифеста, переведённое - техническое имя `name` показывается рядом в
`code`).

Включение/выключение каждого плагина + модал **настройки**, генерируемый из
`config.schema.json` (типы `string`, `text`, `integer`, `number`,
`password`, `bool`, `enum`, `color`, `list`). Колонка **Доступ
пользователей** ограничивает активированный плагин админ-поверхностью
(страница `/{admin_path}`, `/api/admin/*`, админ-сессии): он становится
инертным для пользователей - см. [plugins.md](plugins.md). По умолчанию не
отмечена (авторизовать явно); отсутствует у плагинов, объявляющих только
хуки `admin.*` (нет пользовательской поверхности).

**Установка / обновление с GitHub**: плагины читаются напрямую в запертом
репозитории (`GitHubClient::REPO`, тот же, что у апдейтера ядра) на ref
`update.plugins_ref` - `'release'` = тег последнего релиза по умолчанию,
`'main'` в dev (push `plugin.json` публикует обновление, релиз не требуется).
Каждый скачанный через `raw.githubusercontent.com` файл проверяется по sha1
git-blob.
Каталог загружается при открытии вкладки (кэш общий с проверкой ядра) и
обновляем кнопкой **обновить** справа вверху; неустановленные записи
каталога перечислены внизу таблицы плагинов:

- кнопка **Обновить** на установленных плагинах, когда опубликована более
  новая версия (старая папка сохраняется в
  `storage/update/plugins/backup-<name>-<ts>` - сохраняется одна,
  автоматический откат при сбое);
- кнопка **Установить** на отсутствующих записях каталога - только что
  установленный плагин по умолчанию **выключен**;
- кнопка **Удалить**: **окончательное** удаление папки и конфигурации
  (строка `plugins` очищается), без резервной копии;
- `min_app`/`max_app` удалённого `plugin.json`: несовместимая с
  `APP_VERSION` запись помечается *несовместимой*, и её установка
  отклоняется.

### Миграция webmail (RainLoop / SnappyMail)

Если плагин `webmail-migration` активен, страница **Миграция webmail**
появляется в боковом меню (перед *О программе*): она мигрирует данные папки
`data/_data_/_default_/` установки **RainLoop или SnappyMail**, указанной
по **серверному пути** или **загрузкой ZIP** (распаковка в `storage/tmp`,
очищается выделенной кнопкой или через 2 ч).

- **Анализировать**: инвентаризация без записи (домены `*.ini`/`*.json`,
  найденные аккаунты, объёмы контактов/идентичностей/ключей/настроек на
  пользователя);
- **Запустить импорт**: идемпотентный импорт - недостающие домены,
  контакты (книги по аккаунту + глобальная + PDO DSN, объявленная в
  `application.ini`, частоты и типы email сохранены, удалённые контакты
  исключены), идентичности (по умолчанию = пустой `Id`), известные
  настройки пользователя (сообщений на страницу, обновление, автосохранение
  контактов, системные папки, тема если есть) и armored PGP-ключи.
  Повторяем без дубликатов.

Импортируются только аккаунты, соответствующие **существующему
пользователю**; остальные перечислены в отчёте. Пароли дополнительных
аккаунтов невосстановимы (зашифрованы исходным webmail) - пересоздавать
вручную. Sieve-фильтры живут на почтовом сервере: импортировать нечего.

На стороне пользователя вкладка *Настройки > Контакты* также предлагает
**импорт** `.vcf`/`.csv`/`.sqlite` (книга `AddressBook.sqlite`
RainLoop/SnappyMail - в многопользовательской книге берутся только
контакты аккаунта) и **экспорт** `.vcf`, покрывающий любую другую книгу,
включая ручной экспорт SnappyMail.

### Темы

- тема **по умолчанию** (пишет `user_defaults.theme`);
- **авторизация** по теме (`allowed`): пользователь может выбрать только
  авторизованную тему (дефолтная всегда выбираема);
- модал **настройки** темы (те же типы + `color`);
- отображение цепочки наследования (`extends`).

См. [themes.md](themes.md).

### О программе

Версия (`APP_VERSION`), PHP/SAPI/лимиты, драйвер и размер базы, пути,
загруженные расширения. Ссылка на официальный сайт показана в
navbar. Заголовочная карточка также интегрирует **обновления** через GitHub
Releases (проверка, скачивание, применение, восстановление):

- *Проверить* > *Скачать* > *Применить* > автоматическая финализация
  миграций; состояния сохранены в `storage/update/state.json`;
- при распаковке `files.sha256` (помодульный манифест пакета) проверяется,
  требования пакета (`APP_REQ_PHP`/`APP_REQ_FROM` в его `App.php`: версия
  PHP, минимальная исходная версия) контролируются, а локально изменённые
  файлы сигнализируются до применения;
- во время копирования API пользователя отвечает 503 (флаг
  `storage/update/applying`, страница обслуживания на стороне web -
  истекает через 15 мин при сбое);
- каждый перезаписанный файл сохраняется в `storage/update/backup-<ts>` с
  `manifest.json` (версия, `schema_version`, списки); под SQLite база
  (`webmail.sqlite` + `db/users/*.sqlite`) копируется после checkpoint WAL -
  под MariaDB внешняя копия (`mysqldump`) остаётся на админе
  (предупреждение перед применением);
- *Восстановить* (rollback): восстанавливает файлы последней копии, удаляет
  созданные файлы и переписывает SQLite-базы; под MariaDB отказ, если
  схема продвинулась (восстановите дамп, затем подтвердите принуждение);
- баннер "схема новее кода" сигнализирует откат файлов без восстановления
  базы;
- действие *Сбросить* для отказа от скачанного/распакованного пакета.

> Официальный репозиторий заперт в `GitHubClient::REPO` и **публичный**:
> проверка работает без настройки и токена (отключена лишь пока константа не
> заполнена). `update.channel` остаётся редактируемым здесь;
> `update.repo` задаётся вручную в `config.php`.

## 3. Запись `config.php`

Админ пишет `config.php` **по разделам**, атомарно (временный файл +
`rename`, `chmod 0600`), сохраняя непредоставленные ключи. Если
`app/config/` не записываем, интерфейс указывает это (`saved_readonly`), и
изменения показываются, но не персистируются.

## 4. Проверка подключения

В *Домены*, **Проверить подключение** валидирует протокол активной вкладки
модала (IMAP, SMTP или Sieve - другие вкладки тестируют IMAP), а
**Обнаружить** заполняет поля без сохранения. Детекция (`DomainDetector`)
работает независимо от `autodetect.enabled`. Ручное сохранение домена
стирает маркер "авто-обнаружен" (`options.detected`).
