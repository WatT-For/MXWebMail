# Решение проблем / FAQ

*Переведено с французского - французская версия является исходной.*

## Установка

**Все URL перенаправляют на `/setup/`**
Нормально: блокировка `app/storage/INSTALLED` отсутствует. Завершите
установку или создайте файл вручную после размещения `config.php`.

**Мастер показывает "config/ не записываема"**
Неблокирующее предупреждение: скопируйте показанное содержимое в
`app/config/config.php` вручную, затем перезапустите установку. Проверьте
также, что `app/storage/` записываема (блокирующее).

**Тест подключения MariaDB не проходит**
Проверьте host/порт/учётные данные и что пользователь имеет право создавать
базу (`CREATE DATABASE`). Charset должен быть `utf8mb4`.

## Подключение / вход

**Ни один пользователь не может войти после установки**
При `restrict_domains = true` (по умолчанию) нужна **хотя бы одна именованная
доменная запись** в таблице (wildcard `*` игнорируется для этой проверки).
Установщик пытается её обнаружить; иначе создайте в *Домены*.

**Вход отклонён без причины (аккаунт заблокирован)**
- Слишком много попыток: подождите `login_lock_seconds` (по умолчанию
  300 с) или очистите `app/storage/cache/login_attempts.json`.
- Плагины `black-list`/`white-list` могут отклонять вход (404/403 или
  общая ошибка в зависимости от `auth_error`).
- Пользователь `disabled` отклоняется даже с действительной сессией.

**Вход админа не работает**
- Локальный аккаунт (`admin_user`): проверьте `admin_password_hash` и
  возможный TOTP.
- Fallback IMAP: пользователь должен иметь `is_admin = 1`.
- `admin_ip_allowlist` может блокировать ваш IP.

## Почтовые серверы

**Невозможно подключиться к IMAP/SMTP-серверу**
Используйте кнопку **Проверить подключение** в *Домены* (результат по
протоколам). Частые причины: несогласованный порт/шифрование (993/ssl vs
143/tls), самоподписанный сертификат (см.
`ssl.verify_certificate`/`ssl.allow_self_signed`) или файрвол.

**Самоподписанный сертификат отклонён**
`ssl.verify_certificate = false` или `ssl.allow_self_signed = true`
(использовать только с полным пониманием последствий).

**Домен не определяется автоматически**
`autodetect.enabled` по умолчанию выключен. Включите его или используйте
кнопку **Обнаружить** страницы *Домены*.

**"Отметить как спам" не фильтрует следующие письма**
Кнопка перемещает сообщение в папку Нежелательная (или ставит IMAP-keyword
`$Junk`, если у сервера нет папки Junk) - она ничему не учит сервер.
Sieve-фильтры применяются только при доставке: шаблон *Anti-spam* мастера
(Настройки > Фильтры) сортирует письма, помеченные MTA как
`X-Spam-Flag: YES`. Автоматическое обучение (spam/ham) требует настройки
со стороны сервера - Dovecot IMAPSieve (скрипт report-spam/ham, срабатывающий
при копировании в/из Junk, что инициирует MOVE приложения) или
rspamd/sa-learn.

## Безопасность / HTTPS

**Сайт остаётся на HTTP за обратным прокси**
Заполните `trusted_proxies` (IP прокси), чтобы `X-Forwarded-Proto`
учитывался, затем включите `force_https` / `hsts`.

**Rate-limit или allowlist не видят реальный IP**
Та же причина: без `trusted_proxies` `REMOTE_ADDR` используется как есть.

**Favicon не показывается**
Загруженный favicon должен быть ≤ 512 КБ (ico/png/svg/jpg/webp); иначе
остаётся значок по умолчанию.

## Данные / журналы

**Потеря `app.key`**
Все сохранённые учётные данные становятся нерасшифруемыми: пользователи
должны переподключиться. Всегда делайте копию `app.key`.

**Где журналы?**
`app/storage/logs/app.log` (прикладной), `mail.log` (протоколы
IMAP/SMTP/Sieve, если `logs.enabled`) и журнал auth (`auth_logging`).
Видны в админе (*Журналы*). Интеграция fail2ban:
[fail2ban.md](fail2ban.md).

**Переход на MariaDB опустошил данные**
Ожидаемое поведение: смена `db_dsn` начинается с чистой схемы (файлы
контактов пользователей сохраняются). Инструмента миграции данных нет.

## Обновления

**"Ошибка: Не найдено на GitHub … приватное репо или отсутствующий ресурс"**
Официальный репозиторий заперт (`GitHubClient::REPO` =
`WatT-For/MXWebMail`) и **публичный**: токен не требуется. GitHub
возвращает 404 - не 403 - для отсутствующего ресурса или недостаточного
доступа; сообщение указывает виновный эндпоинт (`releases/latest`,
`commits/…` или путь `raw` каталога плагинов). Устойчивый 404 обычно
означает отсутствующий ресурс (релиз не опубликован, неизвестный
`update.plugins_ref`). Случай "приватное репо" касается только форка,
настроенного через `update.repo` + PAT в `config.php`.

**HTTP 404 на `…/releases/download/…` (каталог плагинов или скачивание обновления)**
На публичном официальном репо `browser_download_url` работает. Случай
имеет смысл только для приватного форка через `update.repo`:
`browser_download_url` возвращает там 404 даже с действительным токеном -
исправлено с 0.36.1, ассеты тогда скачиваются через эндпоинт API
`releases/assets/<id>`, когда PAT настроен в `config.php`.

**Сайт отвечает 503 "update" / страница обслуживания во время обновления**
Нормально: флаг `app/storage/update/applying` перекрывает API пользователя
во время копирования файлов (никогда смесь старого/нового кода). Снимается
в конце; если остался после сбоя, истекает сам через 15 мин - или удалите
`app/storage/update/applying` вручную.

**"Ожидающие миграции" после обновления**
Финализация (`/api/admin/update/finalize`) не выполнилась: кнопка
*Финализировать* в *О программе*, или в CLI `php app/bin/post-update.php`.
Без действия миграции всё равно применятся при следующем запросе (ленивая
миграция), но предпочтительно контролировать их.

**Откат после обновления (rollback)**
Кнопка *Восстановить* в *О программе*: восстанавливает файлы из
`app/storage/update/backup-<ts>` (3 последних бэкапа сохраняются), удаляет
созданные файлы и переписывает сохранённые SQLite-базы. Под **MariaDB**
миграции необратимы: сначала восстановите базу из вашего `mysqldump`,
затем повторите откат (предлагается принудительное подтверждение). Чтобы
начать с нуля: переустановите исходный пакет и восстановите `app/storage/`
(включая `app.key` и `db/`).

**Баннер "схема базы новее кода"**
`meta.schema_ahead`: установленный код старше схемы (откат файлов без
восстановления базы, или развёрнут более старый пакет). Восстановите базу
или повторно примените соответствующую версию; миграции остаются
приостановленными пока существует разрыв.

## Разное

**"Переслать как есть" (bounce): получатель видит письмо как спам?**
Возможно: пересылка ломает SPF/DMARC на конечной стороне (сервер отправки
больше не соответствует исходному отправителю) - нормальное поведение
bounce, заголовки `Resent-*` документируют ретрансляцию. Чтобы сохранить
аутентификацию, предпочитайте классическую пересылку.

**Под Nginx доступны ли приватные папки?**
Нет, если `root` указывает на `public/` и блок `location ~ /\.` +
`^/(app|dist)` присутствует. Никогда не направляйте `root` на корень
проекта.

**Ошибка 403 "cross_site" на легитимном запросе**
Защита `Sec-Fetch-*` отклонила запрос. Если вы интегрируете легитимный
внешний API, добавьте правило в `secfetch_allow`.

**Отладка внутренней ошибки (500)**
Временно включите `debug = true` (никогда в продакшене), чтобы увидеть
сообщение, затем смотрите `app.log`.
