# Домены и почтовые серверы

*Переведено с французского - французская версия является исходной.*

Серверы IMAP/SMTP/Sieve настраиваются **по доменам** в админ-панели
(*Домены*). Каждый домен описывает, как достичь почтового сервера его
пользователей.

## 1. Поля домена

| Поле | Значение |
|---|---|
| `name` | Имя домена (напр. `example.com`), или `*` для catch-all. |
| `imap_host` | Хост IMAP-сервера. |
| `imap_port` | Порт IMAP (по умолчанию `993`). |
| `imap_encryption` | `ssl` (по умолчанию), `tls` (STARTTLS) или `none`. |
| `smtp_host` | Хост SMTP-сервера (отправка). |
| `smtp_port` | Порт SMTP (по умолчанию `465`). |
| `smtp_encryption` | `ssl` (по умолчанию), `tls` или `none`. |
| `sieve_host` | Хост ManageSieve (опционально). |
| `sieve_port` | Порт Sieve (по умолчанию `4190`). |
| `active` | Включить/выключить домен. |

## 2. Расширенные опции (`options`, JSON)

Поле `options` принимает JSON-объект с тонкими настройками по домену:

- `whitelist` - список разрешённых адресов для этого домена;
- `secondary_only` - домен используется только как **дополнительный
  аккаунт** (добавление аккаунта из уже подключённого пользователя);
  первичный вход отклоняется с "Домен зарезервирован для дополнительных
  аккаунтов";
- `oauth` - OAuth2-провайдер домена (`google`, `microsoft`, `yahoo`):
  дополнительные аккаунты добавляются через согласие провайдера (popup),
  никогда паролем (см. §8);
- `imap.shortLogin` - обрезать логин;
- `imap.lowerLogin` - принудительный логин в нижнем регистре;
- `imap.timeout` - таймаут IMAP-подключения;
- `imap.disabled_capabilities` - отключаемые IMAP-capabilities (дефектные
  серверы). Пример: `ESORT` для сервера, объявляющего его без реализации
  опций возврата RFC 5267 (`RETURN (PARTIAL …)`) - webmail уже обнаруживает
  этот случай и сам переключается на классическую сортировку; ключ служит
  только если детекция не применяется (кэш выключен);
- `imap.body_text_limit` - макс. размер (байт) извлекаемых текстовых тел
  при открытии сообщения (по умолчанию `0` = без лимита; потолок ~256 K
  экономит fetch очень длинных рассылок);
- `imap.message_list_limit` - свыше (по умолчанию `10000` сообщений в
  папке) MailSo избегает server-SORT и кэширует список UID в фоне;
- `smtp.useAuth` - форсировать/отключить SMTP-аутентификацию;
- `smtp.timeout` - таймаут SMTP-подключения;
- `sieve.encryption` - шифрование Sieve-подключения.

## 3. Домен `*` (catch-all)

Домен `*` предоставляет **параметры по умолчанию**, применяемые к любому
необъявленному домену - но только когда `restrict_domains = false`: под
`restrict_domains` `*` игнорируется и не может авторизовать первичный
вход. Это простейший способ обслуживать несколько доменов за одним
почтовым сервером.

## 4. Разрешение домена при входе

При входе домен определяется так:

1. Если пользователь вводит логин с `@домен`, используется этот домен.
2. Иначе применяется `default_domain`: `auto` (по умолчанию) = HTTP-хост
   без `www.` и порта; фиксированное имя; или `''` (никакой).
3. Если `restrict_domains = true` (по умолчанию), принимаются только
   **именованные** домены из таблицы (`*` и детекция игнорируются) -
   **создайте поэтому хотя бы один домен до любого входа**.

## 5. Автоматическая детекция

`autodetect.*` (по умолчанию выключен) позволяет обнаружить конфигурацию
неизвестного домена в момент входа:

- `enabled`: включает детекцию;
- `use_ispdb`: опрашивает базу Mozilla (`autoconfig.thunderbird.net`);
- `probe`: зондирует `imap.`/`mail.`/`smtp.<домен>`.

Порядок детекции: DNS SRV > autoconfig Mozilla > MX > зондирование портов.

Sieve обнаруживается независимо от источника: `_sieve._tcp` (SRV), иначе
зондирование порта **4190** на `sieve.<домен>` (если `probe` активен или
через кнопку *Обнаружить*), затем на найденном IMAP-хосте - Dovecot почти
всегда отдаёт ManageSieve на том же хосте. Шифрование настраивать не нужно:
подключение переключается на STARTTLS автоматически, когда сервер его
объявляет.

Кнопка **Обнаружить** страницы *Домены* запускает ту же детекцию по
требованию, независимо от `autodetect.enabled`, и заполняет поля домена.

> Установщик `/setup/` тоже пытается эту детекцию на хосте vhost (и его
> родителях), чтобы автоматически создать первый домен.

## 6. Тест

Кнопка **Проверить подключение** валидирует протокол активной вкладки
модала (IMAP, SMTP или Sieve; другие вкладки тестируют IMAP). Используйте
её после каждого изменения, чтобы проверить, что учётные данные, порты и
шифрование корректны, прежде чем пользователи подключатся.

## 7. Типичный случай: один почтовый сервер

Для единственного сервера (напр. Postfix + Dovecot на `mail.example.com`,
обслуживающего `example.com`):

1. Создайте домен `example.com` с `imap_host = mail.example.com`,
   `smtp_host = mail.example.com` и, возможно, `sieve_host`.
2. Оставьте `default_domain = auto` и `restrict_domains = true`.
3. Пользователи входят `user@example.com` или просто `user` (домен
   выводится из HTTP-хоста).

Мультидоменный вариант: домен `*` с `restrict_domains = false` служит
catch-all - любой необъявленный домен наследует его параметры (см. §3;
внимание, первичный вход тогда остаётся возможным на всех доменах -
`secondary_only` может его отклонить, см. §8).

## 8. Публичные домены как дополнительный аккаунт (Gmail, Outlook, Yahoo)

Gmail, Outlook.com и Yahoo больше не принимают IMAP-аутентификацию простым
паролем - добавление этих аккаунтов происходит через **OAuth2** (согласие в
popup, затем XOAUTH2/OAUTHBEARER для IMAP и SMTP).

Учётные данные OAuth2-приложения (client ID, secret, tenant Microsoft) -
**собственные каждого пользователя**: админ не регистрирует никакое
приложение - он только авторизует провайдера на домене. Каждый пользователь
создаёт собственное приложение в консоли разработчиков провайдера.

### Настройка (админ)

Эти три домена **предсозданы при установке** (дополнительный аккаунт +
OAuth-провайдер уже заданы). Если вы их удалили, пересоздайте так:

1. **Создайте домен** (*Домены > Добавить* или кнопка *Обнаружить*):
   `imap.gmail.com:993` / `smtp.gmail.com:465` для Gmail,
   `outlook.office365.com:993` / `smtp.office365.com:587` для Outlook,
   `imap.mail.yahoo.com:993` / `smtp.mail.yahoo.com:465` для Yahoo.
2. Отметьте **Только дополнительный аккаунт** (первичный вход отклонён) и
   выберите провайдера в **Auth OAuth2**.

### Регистрация приложения (пользователь)

При первом добавлении аккаунта домена webmail запрашивает учётные данные
приложения и регистрирует их для пользователя - затем управляются в
*Настройки > OAuth2-приложения* (одно приложение на провайдера,
переиспользуемое для всех аккаунтов этого провайдера). Redirect URI для
объявления в консоли: `<base>/api/oauth/callback`.

- **Google** (Cloud Console > APIs & Services > Credentials > OAuth
  Web-клиент, scope `https://mail.google.com/`): scope *restricted* -
  приложение в режиме "Testing" ограничено ~100 тестовыми пользователями и
  его refresh-токены истекают через ~7 дней; продакшен требует верификации
  Google.
- **Microsoft** (Entra > App registrations, `signInAudience`, включающая
  личные аккаунты): делегированные разрешения "Office 365 Exchange Online"
  `IMAP.AccessAsUser.All` + `SMTP.Send`, scope `offline_access` неявный.
  Возможен баннер "непроверенный издатель" при согласии (неблокирующий).
- **Yahoo** (Developer Console > приложение OpenID Connect + Mail API,
  scope `openid`, `mail-r`, `mail-w`): доступ к Mail API требует
  **предварительного одобрения Yahoo** (форма запроса + ручная рецензия), а
  распространение redirect URI может занять ~24 ч.

### Работа

- Пользователь добавляет аккаунт из меню аккаунтов или *Настройки >
  Аккаунты*: ввод адреса > (первый раз: ввод учётных данных приложения) >
  popup согласия > аккаунт появляется с бейджем провайдера. *Настройки >
  Аккаунты* позволяет также смену, обновление учётных данных, повышение до
  основного аккаунта и удаление.
- Дополнительный аккаунт может быть **повышен до основного** (звезда в
  *Настройки > Аккаунты*) - флаг `secondary_only` домена блокирует только
  *первичный вход*, не это повышение.
- *Refresh token* хранится зашифрованным (`accounts.imap_pass`); каждое
  IMAP/SMTP-подключение обменивает эфемерный access token. Microsoft и
  Yahoo **перевыпускают refresh token при каждом использовании**: он
  автоматически заменяется в базе.
- Secret приложения шифруется (`oauth_apps.secret`, тот же механизм, что
  пароли) и никогда не возвращается в интерфейс - "пусто = без изменений"
  при редактировании.
- **Изменение или удаление приложения** ломает связанные аккаунты: refresh
  token остаётся привязан к исходному client_id - удалите и добавьте
  аккаунт заново.
- ManageSieve у этих провайдеров нет: Sieve-фильтры недоступны на
  OAuth-аккаунтах.

Комбинация `secondary_only` на домене `*` с обычными внутренними доменами
резервирует первичный вход за перечисленными доменами, оставляя
дополнительные открытыми везде - полезно без `restrict_domains`.
