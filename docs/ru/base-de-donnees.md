# База данных

*Переведено с французского - французская версия является исходной.*

MXWebMail работает с **SQLite** (по умолчанию) или **MariaDB/MySQL**. Драйвер
выбирается через `db_dsn` в `config.php`.

## 1. Подключение

- `db_dsn = 'sqlite'` > `app/storage/db/webmail.sqlite` (режим WAL +
  `foreign_keys`).
- Иначе полный PDO DSN (напр.
  `mysql:host=localhost;dbname=mxwebmail;charset=utf8mb4`) с
  `db_user`/`db_pass`.

Опции PDO: `ERRMODE_EXCEPTION`, `FETCH_ASSOC`, `EMULATE_PREPARES=false`.

## 2. Миграции

Схема **переносима** между SQLite/MariaDB (автоинкрементные первичные ключи
адаптированы под драйвер). Миграции версионируются (`meta.schema_version`) и
применяются автоматически при первом доступе к базе (`App::db()`), включая
установку.

После обновления кода вкладка *О программе* запускает **финализацию**
(`/api/admin/update/finalize`): миграции новой версии выполняются в
админ-контексте, затем мигрируются контактные базы пользователей (база в
ошибке журналируется и повторяется при следующем доступе). В качестве
резерва: `php app/bin/post-update.php` повторяет миграции в CLI. Если схема
новее кода (откат файлов без восстановления базы), ставится
`meta.schema_ahead` и сигнализируется в *О программе* - миграции тогда
приостановлены.

## 3. Глобальные таблицы

| Таблица | Содержание |
|---|---|
| `meta` | пары ключ/значение (`schema_version`, `contacts_moved`, …). |
| `users` | `username` (уникальный), `display_name`, `is_admin`, `disabled`, `session_epoch` (инкрементируется "Принудительным выходом" - отклоняет активные сессии при следующем запросе), `created_at`, `last_login_at`. |
| `accounts` | IMAP-аккаунты пользователей: `email`, `imap_user`, `imap_pass` (зашифровано), `is_default` (основной аккаунт, изменяется в Настройки > Аккаунты), `position` (порядок отображения дополнительных аккаунтов, перетаскиванием в Настройки > Аккаунты), `auth` (`password`, `google`, `microsoft`, `yahoo` - OAuth2: `imap_pass` хранит тогда зашифрованный *refresh token*). |
| `oauth_apps` | OAuth2-приложения на пользователя: `provider`, `client_id`, `secret` (зашифровано), `tenant` - одно приложение на `(user_id, provider)` (см. [domaines.md](domaines.md) §8). |
| `user_settings` | настройки пользователя (ключ/значение), PK `(user_id, key)`. |
| `identities` | отправительские идентичности: `name`, `email`, `reply_to`, `bcc`, `signature`, `is_default`. |
| `domains` | почтовые серверы по доменам (см. [domaines.md](domaines.md)) + `options` JSON. |
| `plugins` | `enabled`, `user_allowed` (только админ если 0 - по умолчанию), `config` (JSON) по плагину. |
| `themes` | `config` (JSON) и `allowed` по теме. |
| `pgp_keys` | связка OpenPGP (`key_data` armored, `is_private`). |
| `auth_tokens` | токены "Оставаться в системе": `selector` (уникальный), `token` (SHA-256 валидатора, ротируется при каждом использовании), `agent` (User-Agent), `ip` (при выпуске), `last_ip` (последнее восстановление), `created_at`, `last_used_at`, `expires_at`. |

Бывшие таблицы `contacts` / `contact_emails` вынесены из глобальной базы
(см. §5).

## 4. `app.key`

`app/storage/app.key` - мастер-ключ 32 байта (64 hex), генерируется при
первом шифровании учётных данных. Шифрует (XSalsa20-Poly1305, libsodium
secretbox):

- IMAP-пароли в сессии и в `accounts.imap_pass` (и *refresh token* OAuth2
  аккаунтов `auth != 'password'`);
- секреты OAuth2-приложений пользователей (`oauth_apps.secret`);
- секреты плагинов (напр. пароль CardDAV).

**Сделайте резервную копию и никогда его не теряйте**: его потеря делает
недействительными все сохранённые учётные данные (пользователям придётся
переподключиться). Не должен ни отдаваться, ни версионироваться.

## 5. Базы на пользователя (контакты)

Контакты изолированы в индивидуальных SQLite-базах:
`app/storage/db/users/<id>.sqlite` (таблицы `contacts`, `contact_emails`).
Это действует **и под MariaDB**: личные данные остаются в SQLite-файлах.

Миграция `contacts_moved` однократно копирует контакты из глобальной базы в
эти файлы (транзакция + `INSERT OR IGNORE`, самовосстанавливающаяся), затем
удаляет глобальные таблицы.

## 6. Переход с SQLite на MariaDB

1. В админе (*База данных*) укажите DSN/host/порт/имя/пользователя/пароль
   MariaDB. Тест подключения **обязателен** и создаёт базу (`utf8mb4`,
   collation `utf8mb4_unicode_ci`) если её нет.
2. Миграции повторяют схему на новой базе.

> **Важно**: смена `db_dsn` начинается с **чистой схемы** - данные
> (пользователи, домены, настройки) **не мигрируются**. Инструмента
> экспорта нет. Файлы контактов на пользователя при этом остаются
> неизменными.

## 7. Резервное копирование / восстановление

- SQLite: скопируйте `app/storage/db/webmail.sqlite` (+ `db/users/*.sqlite`)
  и `app.key`.
- MariaDB: сделайте дамп базы `mysqldump`, плюс `app.key` и
  `db/users/*.sqlite`.
